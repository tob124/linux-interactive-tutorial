# 教师使用说明

课程作者：**Connor He 和 Astra**  
对象：华南理工大学机械专业研一新生；默认有基本 C/MATLAB 经验，无 Linux 前置要求。  
组织：12 周，每周 6–8 小时。当前基础版提供前 6 周完整学习单元与实验资产，后 6 周为分方向项目规划。

## 培训目标与岗位解释

学生应能在 Linux 上独立组织工程项目、安装和记录软件环境、编写自动化流程、使用远程计算资源、定位程序与数据问题、完成无硬件电机虚拟调试，并用中英文说明复现步骤和结果局限。

课程采用岗位能力映射，而非软件数量考核。高级岗位中的系统设计、HPC 和大型软件经验是后续成长方向，不能全部当作应届生的最低门槛。以下来源核验日期为 2026-09-12；招聘页面会更新，开班前复核岗位地区、年限、校招属性和专业要求。

## 每周教学节奏

每周四个单元：前三个各约 45 分钟，第四个约 60 分钟。另分配 1.5–2 小时独立完成与排障、约 1 小时同伴复现、0.5–1.5 小时阅读和表达。

| 周 | 机械情境与验收重点 | 建议追问 |
|---|---|---|
| 1 | 建立电机实验目录；理解宿主机与容器、用户与权限 | 为什么不能用 777 解决所有权限错误？ |
| 2 | 从包含空电流的日志得到可追溯结果 | 删除采样点后，还能假设等时间间隔吗？ |
| 3 | 独立 Python 环境与 6/9/12 V 参数扫描 | 为什么退出码成功不等于物理结果正确？ |
| 4 | 内部虚拟工作站的 SSH、同步与保活 | 主机指纹和用户公钥分别证明什么？ |
| 5 | 传感器 rad/s→rpm 单位错误 | 如何证明失败测试与修复测试检查的是同一问题？ |
| 6 | 两模型对照、PI 与单位故障诊断 | 测量反馈达到 900 rpm，真实速度就一定正确吗？ |

开始时先让学生预测输出，再运行；出错时先收集证据，再使用提示。参考解用于校对，不应成为复制比赛。每节结束，让学生用自己的话解释一条命令、一项结果和一个错误原因。

第 5 周先通过错误版本的第 1–3 单元检查，再修改代码。修复后重新检查“错误版本应失败”的单元会失败，这是状态检查的预期行为；先前已保存的学习证据仍可用于评审。

## 开班前的真实环境验收

1. 每台机器按 README 准备本地服务、rootless Docker、基础镜像和第 6 周缓存镜像。先确认 cgroup v2 内存和进程限制；不要临时换成 rootful 执行。软件包准备需要网络，课堂运行依赖预缓存。
2. 浏览器打开课程，检查环境页。第 1 周启动终端，确认 `whoami` 为 student、目录为 `/workspace`，安装 tree，完成四个检查。退出后再启动，确认笔记保留。
3. 第 2 周按参考解清洗日志、提交 Git，再改坏一项结果，确认对应检查失败，恢复后再次通过。
4. 第 3 周从本地 wheels 安装四个科学库，真实运行开环及批处理。结果需符合解析稳态，不能只检查是否生成文件。
5. 第 4 周核对启动消息给出的 SSH 指纹，使用课程临时口令 `linuxlab` 安装公钥，完成 rsync 和远程 tmux，取回结果并验证 SHA256。口令仅在隔离内部网络练习使用。重置后服务器密钥会变化，应重新核对。
6. 第 5 周构建 Debug 工程、观察真实测试失败和 GDB 断点；修复单位关系后原测试应全部通过。若 ptrace 被限制，记录并修复课堂容器配置，不伪造日志。
7. 第 6 周真实安装 omc，加载标准库 4.0.0，运行 Modelica 组件模型。完成 Python/Modelica 无负载 12 V、5 s 对照；最大转速误差应小于 1 rpm，最大电流误差小于 0.02 A。此容差属于教学基准。
8. 完成闭环与故障作品，填入学生姓名和自己的英文摘要。导出项目并在独立干净实验中复现。重置功能只在已有导出备份的练习项目中检查。

平台自动测试和真实课堂验收分开记录。目前开发机的 Docker 安装尚未获自动审批通过，因此上述容器流程、SSH/GDB 与 OpenModelica 尚未在该机完成端到端验收。请勿据网页完成度宣称这些环节已验证。

网页关闭后容器仍可能运行，课末点击“停止实验”。学习记录在本地 SQLite，课堂没有教师账号、跨设备汇总、在线排名或教师签名认证。

## 作品与人工评价

基础结业包至少包含 README、参数与单位、依赖版本、运行命令、原始结果、失败与修复证据、分析、英文摘要和模型局限。课程作者固定为 Connor He 和 Astra，学生作者填写本人姓名与贡献；不得把课程署名当作学生署名。

| 维度 | 权重 | 观察证据 |
|---|---|---|
| 正确性 | 40% | 单位、工况、解析关系、测试与模型对照相互一致 |
| 复现性 | 25% | 他人用文档、依赖、输入和命令能得到可比较结果 |
| 排障能力 | 20% | 有现象、假设、证据、定位、最小修复和复测 |
| 技术表达 | 15% | 中英文说明清楚，结论有证据，知道模型边界 |

建议 70 分作为基础结业参考，且正确性至少 28/40、复现性至少 15/25。要求学生现场解释一项失败和一次修复，并完成同伴复现。评分由教师人工完成；网页的“已读 + 答题 + 状态检查”仅表示学习进度，作品页始终明确人工评审尚未进行。

任务检查器面向反馈，不是防作弊或资质认证系统。文本分析质量、工程创新、诚信和口头理解需人工判断；一个包含关键词的报告不自动代表合格作品。

## 进阶项目安排

第 7–12 周每两周一个里程碑，当前版本只提供规划和软件入口：

| 方向 | 7–8 周 | 9–10 周 | 11–12 周 |
|---|---|---|---|
| 机器人与控制 | ROS 2 / Gazebo 单关节执行器 | 差速机器人路线与扰动 | 配置、通信故障恢复及演示 |
| CAE | FreeCAD / Gmsh / CalculiX 支架静力学 | OpenFOAM 管路层流与压降 | 网格敏感性、参数扫描、批处理交付 |
| 工业设备软件 | 虚拟电机 Modbus/MQTT 接口 | 断连、超时、非法指令、告警 | 服务部署、日志与英文诊断说明 |

选一条做深，不要求同时安装所有软件。没有硬件时明确区分物理模型、接口 mock、软件在环与实机试验；不能把仿真结果用于声称验证了真实电机热特性、实时总线或设备安全功能。

## 更新课程

编辑 `scripts/build_content.py` 与 `scripts/build_software.py` 后运行生成器，再运行 README 中的测试。更新依赖时重建镜像、保留镜像 ID 和实际软件版本，并重做受影响的真实实验。Dockerfile 中 Ubuntu 基础镜像和 APT stable 仓库会随时间变化，应由开班镜像固定课堂环境；当前脚本将基础镜像清单保存到 `.state/base-image-manifest.json`。

软件指南链接优先使用官方文档；国内网络无法访问时先由教师准备经过核验的缓存，不让初学者随意添加第三方源。商业软件的 Linux 支持和授权需以机构许可与厂商当期文档为准。
